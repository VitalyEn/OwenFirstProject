# Проверка основной программы ПЛК в симуляции (без СПК210)

Инструкция для **CODESYS 3.5.17.20 (RU, Овен)**, проект «Насосы Крым Обучение».

Проверяем **логику** (`PRG_Main`, FB, `GVL_IO`, `GVL_Process`).  
**Визуализацию** и **реальные модули MU210/MV210** в симуляции не используем.

---

## 1. Что должно быть готово

| Проверка | Где |
|----------|-----|
| **Build** без ошибок | Сборка → Собрать (F11) |
| В **MainTask** только `PRG_Main()` | Конфигурация задач |
| `PRG_HMI` **не обязателен** для логики щита (можно отключить на время теста) |
| DUT `E_LevelState` с константами **LEV_*** (не `LVL_HIGH`) | `import/DUT_Types.txt` |
| Переменные `GVL_IO` **без** привязки `AT %I` / `AT %Q` на время симуляции | см. §2 |

> Если входы привязаны к `%IX` / `%QX`, принудительная подстановка в Watch может **перезаписываться** драйвером I/O. Для симуляции временно уберите `AT` у тестируемых переменных или не подключайте модули в Online.

## 2. Подготовка к симуляции (один раз)

### 2.1 Запуск симуляции

1. **Сборка → Собрать** (F11), 0 errors.
2. Меню **Онлайн**:
   - **Онлайн → Симуляция** (если есть), или
   - **Онлайн → Вход** → устройство **Simulation** / эмулятор (если в списке).
3. После входа: **Онлайн → Пуск** (или зелёная кнопка Run) — цикл MainTask должен крутиться.

Если пункта «Симуляция» нет — у таргета СПК210 полной эмуляции может не быть; см. [§8](#8-если-симуляция-недоступна).

### 2.2 Окно наблюдения (Watch)

**Онлайн → Добавить в список наблюдения** (или откройте GVL и **Подготовить столбцы**).

Рекомендуемый минимальный список:

**Входы (подставляем вручную):**
- `GVL_IO.LVL_High`, `LVL_Mid`, `LVL_Low`, `Flood`
- `GVL_IO.SA1_Auto` … `SA7_Auto`
- `GVL_HMI.HMI_AutoEnable`, `HMI_ResetAlarm`, `HMI_FillValveForce`

**Внутреннее / процесс:**
- `GVL_Process.WorkMode`, `FillPhaseDone`, `SystemReady`, `SystemRunning`
- `GVL_Process.GlobalStop`, `Alarm_Active`, `Alarm_DryRun`, `Alarm_Flood`

**Выходы команд:**
- `GVL_IO.CMD_KM7`, `CMD_KM8`, `CMD_VFD1_Start`, `CMD_VFD2_Start`
- `GVL_IO.VFD1_SpeedCmd`, `VFD2_SpeedCmd`

**Уровень (локально в PRG_Main):** добавьте в Watch экземпляр `PRG_Main.LevelMon` → поля `State`, `AllowRun`, `NeedFill`, `EmergencyStop`  
(в дереве: `PRG_Main` → `LevelMon` → двойной клик / перетащить в Watch).

### 2.3 Принудительная подстановка (Force)

1. Выделите ячейку переменной в Watch.
2. **Принудительно** (F7) → введите `TRUE` / `FALSE` / число.
3. Снимите принуждение: снова F7 или **Онлайн → Сбросить принудительные значения**.

## 3. Таблица уровней (FB_LevelMonitor)

Эта таблица проверяет **только** функциональный блок `FB_LevelMonitor` (экземпляр `PRG_Main.LevelMon`).  
Он вызывается каждый цикл `PRG_Main` и по четырём дискретным входам из `GVL_IO` формирует состояние уровня и флаги для автомата.

Исходник логики: `import/FB_LevelMonitor.txt`. Приоритет веток в коде:

1. `Flood` **или** `LVL_Low` → **LEV_FAULT**
2. иначе `LVL_High` → **LEV_HIGH**
3. иначе `LVL_Mid` → **LEV_MID**
4. иначе (все уровни сняты) → **LEV_LOW**

> Константа **LEV_EMPTY (0)** в DUT есть, но FB её **не выставляет** — при «все нули» ожидайте **LEV_LOW (1)**.

### 3.1 Что нужно до начала

| Шаг | Действие |
|-----|----------|
| 1 | Выполнены §1 и §2: сборка без ошибок, **Онлайн → Пуск**, цикл MainTask идёт |
| 2 | В Watch есть `GVL_IO.LVL_High`, `LVL_Mid`, `LVL_Low`, `Flood` |
| 3 | В Watch добавлен `PRG_Main.LevelMon` → поля **`State`**, **`AllowRun`**, **`NeedFill`**, **`EmergencyStop`** |
| 4 | У тестируемых `LVL_*` / `Flood` **нет** привязки `AT %I` (или I/O не подключён при Login), иначе Force не сработает — см. §9 |

Имена в проекте:

| В Watch / Force | Смысл |
|-----------------|--------|
| `GVL_IO.LVL_High`, `LVL_Mid`, `LVL_Low` | Дискреты щита (DI) |
| `GVL_IO.Flood` | Затопление |
| `PRG_Main.LevelMon.State` | Перечисление **E_LevelState** (не путать с `LVL_High`!) |

### 3.2 Как читать столбец State

В Watch `State` может отображаться **именем** (`LEV_LOW`) или **числом** (`1`). Оба варианта верны:

| Число | Имя в DUT | Когда в таблице |
|:-----:|-----------|-----------------|
| 0 | LEV_EMPTY | FB не использует в этих тестах |
| 1 | LEV_LOW | Строка 1 — «пусто», нужен долив |
| 2 | LEV_MID | Строка 2 — рабочий уровень |
| 3 | LEV_HIGH | Строка 3 — верх, наполнение завершено |
| 4 | LEV_FAULT | Строки 4–5 — авария |

Столбцы **AllowRun**, **NeedFill**, **EmergencyStop** в таблице — **0/1**; в Watch это `FALSE`/`TRUE`.

### 3.3 Правило подстановки

Подставляйте **ровно одну строку таблицы за раз**:

- Для строки задайте указанные **TRUE** (Force `TRUE` или `1`).
- Все остальные из четырёх входов (`LVL_High`, `LVL_Mid`, `LVL_Low`, `Flood`) принудительно **FALSE**.
- Не оставляйте «висящие» TRUE от прошлого шага — иначе получите другую ветку приоритета (например, `LVL_Low` + `LVL_Mid` → всё равно **LEV_FAULT**, потому что Low выше по приоритету).

**Быстрый сброс перед новой строкой:** выделите четыре входа в Watch → **Сбросить принудительные значения** → затем Force только по новой строке.

### 3.4 Пошаговый порядок проверки (рекомендуется)

Проверяйте строки **сверху вниз** — от нормальных режимов к авариям.

#### Строка 1 — низкий уровень (нужен долив)

| Вход | Значение |
|------|----------|
| LVL_High, LVL_Mid, LVL_Low, Flood | все **FALSE** |

**Ожидание в Watch (`PRG_Main.LevelMon`):**

| Поле | Значение |
|------|----------|
| State | **LEV_LOW** (1) |
| AllowRun | FALSE |
| NeedFill | TRUE |
| EmergencyStop | FALSE |

Смысл: насосы по уровню **не разрешены**, автомат может запросить фазу наполнения (`NeedFill`) — см. §5.2.

#### Строка 2 — средний уровень (работа)

| Вход | Значение |
|------|----------|
| LVL_Mid | **TRUE** |
| LVL_High, LVL_Low, Flood | **FALSE** |

**Ожидание:** State = **LEV_MID** (2), AllowRun = TRUE, NeedFill = FALSE, EmergencyStop = FALSE.

#### Строка 3 — верхний уровень

| Вход | Значение |
|------|----------|
| LVL_High | **TRUE** |
| LVL_Mid, LVL_Low, Flood | **FALSE** |

**Ожидание:** State = **LEV_HIGH** (3), AllowRun = TRUE, NeedFill = FALSE, EmergencyStop = FALSE.

В автомате по этому состоянию завершается фаза наполнения (`FillPhaseDone`) — §5.2, шаг 3.

#### Строка 4 — сухой ход (низкий датчик сработал)

| Вход | Значение |
|------|----------|
| LVL_Low | **TRUE** |
| LVL_High, LVL_Mid, Flood | **FALSE** |

**Ожидание:** State = **LEV_FAULT** (4), AllowRun = FALSE, NeedFill = FALSE, EmergencyStop = TRUE.

> **Не путать `LVL_Low` и `LEV_LOW`.**  
> - **`GVL_IO.LVL_Low = TRUE`** — на щите **сработал** дискретный датчик «низкий уровень» (сухой ход / авария). FB даёт **LEV_FAULT** и **EmergencyStop = TRUE** — это **норма**, строка 4 пройдена.  
> - **`LEV_LOW` в State** — логическое «емкость пустая, нужен долив», когда **все** `LVL_High`, `LVL_Mid`, `LVL_Low`, `Flood` = **FALSE** (строка 1). Вход `LVL_Low` при этом должен быть **0**.

> Даже если одновременно зажать Mid/High, при **LVL_Low = TRUE** всегда будет **LEV_FAULT** — так задумано в FB.

#### Строка 5 — затопление

| Вход | Значение |
|------|----------|
| Flood | **TRUE** |
| LVL_High, LVL_Mid, LVL_Low | **FALSE** |

**Ожидание:** те же, что в строке 4 — **LEV_FAULT**, EmergencyStop = TRUE.

Отдельно проверьте комбинацию **Flood + любой уровень** — результат тот же (ветка Flood/Low в коде одна).

### 3.5 Сводная таблица (для сверки)

Подставляйте **только одну** комбинацию за раз (остальные уровни = FALSE).

| № | LVL_High | LVL_Mid | LVL_Low | Flood | State (ожид.) | AllowRun | NeedFill | EmergencyStop |
|:-:|--------:|:-------:|:-------:|:-----:|----------------|----------|----------|---------------|
| 1 | 0 | 0 | 0 | 0 | LEV_LOW (1) | 0 | 1 | 0 |
| 2 | 0 | 1 | 0 | 0 | LEV_MID (2) | 1 | 0 | 0 |
| 3 | 1 | 0 | 0 | 0 | LEV_HIGH (3) | 1 | 0 | 0 |
| 4 | 0 | 0 | 1 | 0 | LEV_FAULT (4) | 0 | 0 | 1 |
| 5 | 0 | 0 | 0 | 1 | LEV_FAULT (4) | 0 | 0 | 1 |

**Критерий «строка пройдена»:** все пять полей в `PRG_Main.LevelMon` совпадают с таблицей **не менее 2–3 циклов** подряд (достаточно увидеть стабильные значения в Watch при работающем Run).

### 3.6 Как подставлять в CODESYS (кратко)

1. **Онлайн → Добавить в список наблюдения** — переменные из §3.1.
2. Для `GVL_IO.LVL_High` (и остальных трёх): ячейка → **Принудительно** (F7) → `FALSE` или `TRUE`.
3. Смотрите **`PRG_Main.LevelMon.*`** — их Force **не нужен** (они выходы FB).
4. Переход к следующей строке: снимите Force со всех четырёх входов (F7 или **Сбросить принудительные значения**) → задайте новую комбинацию.

### 3.7 Если результат не совпадает

| Симптом | Что проверить |
|---------|----------------|
| `State` «залип» или не меняется | MainTask не в Run; смотрите не копию переменной, а именно `PRG_Main.LevelMon` |
| Force на `LVL_High` не держится | `AT %I` на переменной — §2, §9 |
| Вместо LEV_LOW показывается 0 / LEV_EMPTY | Смотрите не `GVL_IO`, а выход FB; пересоберите проект после правки DUT |
| При всех 0 — не LEV_LOW | Старый бинарник: **Собрать** (F11) и повторный Login |
| Несколько TRUE на уровнях | Сверьте приоритет §3 (например Low+Mid → LEV_FAULT, не MID) |
| `State` показывает `LVL_HIGH` / ошибка компиляции | В DUT должны быть **LEV_***, не **LVL_*** — `import/DUT_Types.txt` |

### 3.8 Что эта таблица **не** проверяет

- Режимы **Ручной** / **Автомат**, выходы `CMD_*` — §4, §5.
- Сброс `FillPhaseDone`, расписания насосов — §5, §6.
- Таблица §3 подтверждает только корректность **FB_LevelMonitor** и связки `GVL_IO` → `PRG_Main.LevelMon`.

После успешного прохода всех пяти строк отметьте в чек-листе §7 пункт «Таблица уровней §3».

## 4. Режим «Ручной» (WorkMode = MODE_MANUAL)

**Условие:** любой из `SA1_Auto` … `SA7_Auto` = **FALSE** (например, только `SA1_Auto := FALSE`, остальные TRUE).

| Действие | Ожидание |
|----------|----------|
| `SA1_Auto := FALSE` | `CMD_VFD1_Start = TRUE`, `CMD_VFD1_Stop = FALSE` |
| `SA3_Auto := FALSE` | `CMD_VFD2_Start = TRUE` |
| `SA4_Auto := FALSE` | `CMD_KM1 = TRUE` |
| `SA7_Auto := FALSE` | `CMD_KM0 = TRUE` |
| `SA10_ManualOpen := TRUE` | `CMD_KM7 = TRUE` |
| `Flood := TRUE` в ручном | команды ручного режима **без** защиты сухого хода (по коду FB_ManualMode) |

`GVL_Process.WorkMode` должен стать **MODE_MANUAL** (0).

## 5. Режим «Автомат» (WorkMode = MODE_AUTO)

**Условие:** `SA1_Auto` … `SA7_Auto` = **TRUE**, `GVL_HMI.HMI_AutoEnable = TRUE`.

### 5.1 Сброс фазы наполнения

`FillPhaseDone` в **GVL_Process** — **RETAIN**. Перед тестом наполнения:

- Force `GVL_Process.FillPhaseDone := FALSE`
- Force `GVL_Process.SystemReady := FALSE`
- Force `GVL_Process.GlobalStop := FALSE`

### 5.2 Фаза наполнения (ждём верхний уровень)

| Шаг | Force | Ожидание |
|-----|-------|----------|
| 1 | Все уровни 0 | `NeedFill = 1`, `FillPhaseDone = 0` |
| 2 | — | `CMD_KM7 = 1` (долив M4), `SystemRunning = 1` |
| 3 | `LVL_High := TRUE` | `FillPhaseDone = 1`, `SystemReady = 1`, `CMD_KM7` может сброситься после выхода из фазы |
| 4 | `HMI_FillValveForce := TRUE` при низком уровне | `CMD_KM7 = 1` даже без NeedFill |

### 5.3 Рабочий режим (средний уровень)

| Шаг | Force | Ожидание |
|-----|-------|----------|
| 1 | `FillPhaseDone = 1` (уже после верха) | — |
| 2 | `LVL_Mid = 1`, остальные уровни 0 | `SystemRunning = 1`, `LevelMon.AllowRun = 1` |
| 3 | Расписание насосов | см. §6 — иначе `CMD_VFD*` / `CMD_KM*` могут остаться 0 |

### 5.4 Аварийная остановка в авто

| Шаг | Force | Ожидание |
|-----|-------|----------|
| 1 | `LVL_Low = 1` | `GlobalStop = 1`, `Alarm_Active = 1`, `Alarm_DryRun = 1` |
| 2 | Сброс уровня, `Flood = 1` | `Alarm_Flood = 1`, `EmergencyStop` через LevelMon |
| 3 | `HMI_ResetAlarm := TRUE` (импульс) | `GlobalStop = 0`, `Alarm_Active = 0` (обрабатывает PRG_Main) |

### 5.5 Затопление — кран M5

При `Flood = 1` в рабочей фазе (после `FillPhaseDone`):

- `CMD_KM8 = TRUE` (открыть M5 по затоплению)

## 6. Расписания насосов (важно для симуляции)

В `FB_AutoMode` время **`NowHour` / `NowMin` не заполняется** (заглушка 0).  
`FB_Schedule` считает «сейчас» = **00:00**.

**Чтобы насосы по расписанию включились в симуляции:**

1. Откройте **GVL_Schedules** → для теста, например `Sched_N1`:
   - `Enable := TRUE`
   - `StartHour := 0`, `StartMin := 0`
   - `StopHour := 23`, `StopMin := 59`
2. `SA1_Auto := TRUE` (насос в автомате на щите).
3. Уровень **средний** (`LVL_Mid`), `FillPhaseDone = 1`.

Ожидание: `CMD_VFD1_Start = 1` (если нет `VFD1_Alarm` и нет `GlobalStop`).

**Скорость УПП:** при `CMD_VFD1_Start = 1` → `VFD1_SpeedCmd = 1000` (100% из `VFD_Speed_RunPct`).

## 8. Если симуляция недоступна

У **СПК210-07-CS** в Device Repository часто **нет** полноценного SoftPLC.

Варианты:

1. **Только Build** — проверка компиляции (без поведения).
2. Временно сменить устройство проекта на **CODESYS Control Win V3** (отдельный тестовый проект) — только для отладки ST, не для сдачи объекта.
3. **Финальная проверка** — Download на реальный СПК210.

Без Online принудительные значения **не влияют** на выполняющийся код.

## 9. Частые проблемы

| Симптом | Причина | Что сделать |
|---------|---------|-------------|
| Force не меняет `LVL_High` | Переменная на `%IX` | Убрать `AT %I` или не логиниться с I/O |
| Авто не запускается | `HMI_AutoEnable = 0` или SA в ручном | Все `SA*_Auto = 1`, `HMI_AutoEnable = 1` |
| Нет долива | `FillPhaseDone = 1` | Сбросить `FillPhaseDone` |
| Нет насосов в авто | Расписание / время 00:00 | §6 — окно 0:00–23:59 |
| `State` не тот | Конфликт имён LEV/LVL | DUT **LEV_***, DI — **LVL_High** |
| C0373 по CMD_* | Две задачи пишут выход | Для симуляции можно игнорировать |
