# Пункт 5: I/O Mapping без контроллера

Сопоставление переменных GVL_IO с каналами МВ210/МУ210. Физический СПК210 не обязателен.

## Подготовка

1. Выполнены п. 3 (модули в Device Tree) и п. 4 (GVL_IO создан).
2. Откройте карту: **IO_Map.txt** (если IO_Map.md не открывается в редакторе).

## Способ A: I/O Mapping на модуле (рекомендуется)

### Входы MV210-214

1. Device Tree - двойной клик **MV210-214** (первый модуль).
2. Вкладка **I/O Mapping** / **Соотнесение входов-выходов**.
3. Таблица: столбцы Channel (DI1...), Variable, Address.
4. В столбце **Variable** для строки DI1: нажмите ... - выберите `GVL_IO.SA1_Auto`.
5. Повторите по таблице **IO_Map.txt** — только **DI1…DI32** на каждом MV210-214 (например: DI1 — `SA1_Auto`, DI7 — `LVL_High`, DI18 — `DK_QF2`).
6. Второй модуль MV210-214 (A4) — `VFD1_Run`, `FB_KM*`, `M2_Open`… по столбцу DI CODESYS в IO_Map.txt.
7. **Не привязывайте** DK_QF12…DK_QF17 — на схеме их нет.

### Выходы MU210-403

Модуль **MU210-403** — **24 дискретных выхода** (реле/транзисторы). В программе команды — переменные `GVL_IO.CMD_*` типа **BOOL** (`TRUE` = включить выход).

#### 1. Открыть модуль в дереве

1. **Device Tree** (слева) → найдите **MU210-403** (первый на шине или тот, что соответствует листу схемы 4–5).
2. Если модулей **несколько** — привязывайте **каждый отдельно** (см. п. 4 ниже).
3. **Двойной клик** по модулю → откроется редактор устройства.

#### 2. Вкладка I/O Mapping

1. Перейдите на вкладку **I/O Mapping** / **Соотнесение входов-выходов**.
2. В таблице будут строки каналов: **DO1, DO2, … DO24** (иногда в заголовке — **Channel**, **Variable**, **Address**).
3. Столбец **Variable** (Переменная) — сюда назначается переменная из **Application → GVL_IO**.

#### 3. Как назначить переменную на канал

Для каждой строки **DO**:

1. Клик по ячейке **Variable** в строке нужного DO (например **DO17**).
2. Кнопка **`...`** (три точки) или **F2** → откроется выбор переменной.
3. Разверните **Application** → **GVL_IO** → выберите имя, например `CMD_VFD1_Start`.
4. Подтвердите (**OK**). В ячейке появится `GVL_IO.CMD_VFD1_Start`.
5. Повторите для всех задействованных DO по таблице из **IO_Map.txt** (раздел «MU210-403»).

Строки **резерв** (DO2, DO7, DO8, DO22–DO24) можно **оставить пустыми** — переменную не назначайте.

#### 5. Несколько MU210-403 на RS-485

На схеме может быть **2–6** блоков МУ210-403:

1. В Device Tree у каждого модуля свой **Modbus-адрес** (3, 4, 5… — см. `Пункт3_без_контроллера.md`).
2. Откройте **I/O Mapping** **отдельно** для каждого MU210-403.
3. Распределите `CMD_*` по модулям так, как физически выведены цепи на листах 4–5 схемы (один модуль — часть насосов/кранов, второй — остальное).
4. В Excel/заметках зафиксируйте: «MU210 addr 3: DO1=CMD_KM0…» — чтобы на ПНР не перепутать.

#### 6. Проверка привязки DO

1. **Build** (F11) — проект компилируется.
2. **View → GVL Cross Reference** по `CMD_KM1` — должна быть ссылка на `%Q*` / канал DO модуля.
3. Без ПЛК: в **Watch** принудительно `CMD_KM7 := TRUE` — после загрузки на объект выход DO13 должен замкнуть реле KM7 (на стенде).

#### 7. Типичные ошибки (DO)

| Ошибка | Что сделать |
|--------|-------------|
| В списке нет `GVL_IO.CMD_*` | Создайте/обновите **GVL_IO** из `import/GVL_IO.txt` (п. 4 README) |
| Перепутаны DO17/DO18 (пуск/стоп УПП) | Сверить клеммы УПП1 на схеме; пуск и стоп — **разные** DO |
| Один `CMD_KM1` на два DO | Одна переменная — **один** канал; дублировать нельзя |
| Все DO на одном модуле, а на щите два МУ210 | Разнести по двум узлам в Device Tree |

### Выходы MU210-502 (аналоговые, 4–20 mA на УПП)

1. Двойной клик **MU210-502**.
2. Вкладка **I/O Mapping** - аналоговые выходы **AO1**, **AO2**...
3. Привяжите:
   - **AO1** → `GVL_IO.VFD1_SpeedCmd`
   - **AO2** → `GVL_IO.VFD2_SpeedCmd`
4. Масштабирование на модуле должно обеспечить формирование **4–20 mA** при вашем диапазоне задания (например, 0…100%).

### Синхронизация

- Кнопки **Sync** / **Синхронизация** используйте только при подключенном ПЛК.
- Без ПЛК - только ручной ввод Variable.

## Способ B: AT %I / AT %Q в GVL_IO

В Declaration GVL_IO можно указать адрес:

```
SA1_Auto AT %IX.MV210_1.DI1 : BOOL;
```

Имя `%IX.MV210_1` зависит от имени модуля в дереве - CODESYS подскажет при автодополнении после F2.

Без модулей в дереве адреса не появятся.

## Способ C: таблица Excel (до появления ПЛК)

Создайте таблицу:

| Modbus модуль | Канал | GVL_IO | Проверено на объекте |
|---------------|-------|--------|----------------------|
| MV210 addr 1 | DI7 | LVL_High | |

На ПНР перенесите в CODESYS I/O Mapping.

## Проверка без загрузки

1. Build (F11) - нет ошибок "variable not mapped" (если Owen не требует 100% mapping).
2. View - GVL Cross Reference - переменная GVL_IO.SA1_Auto показывает привязку к DI.
3. Online - невозможно без ПЛК; используйте принудительные значения в Watch для отладки логики.

## Отладка логики без I/O

В GVL_IO временно задайте в Watch или в коде (только для теста):

```
LVL_Mid := TRUE;
SA1_Auto := TRUE;
```

Либо отдельная GVL_Sim - не коммитить в финальный проект.

## Частые ошибки

| Проблема | Решение |
|----------|---------|
| Нет вкладки I/O Mapping | Обновить device description Mx210; шаблон с forum.owen.ru |
| Variable недоступна | GVL_IO должен быть создан в Application |
| DI номера не совпадают со схемой | На схеме DI44+ — маркировка проводов; в CODESYS только DI1…DI32. Ориентир — имя в GVL_IO |
| Несколько MU210-403 | Каждый модуль - свой диапазон DO |
